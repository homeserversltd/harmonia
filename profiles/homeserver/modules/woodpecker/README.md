# Woodpecker

This module carries configuration for the household's Woodpecker server and local agent. Birth provides the two executables, the `woodpecker` user and group, a writable `/var/lib/woodpecker`, the enabled units and the instance environment. Harmonia does not install binaries or overwrite the instance environment; it requires those files and maintains the two unit files. The server uses its upstream default SQLite data directory, and the agent stores its registration in `/var/lib/woodpecker/agent.conf`.

The birth seed `/etc/default/woodpecker` contains three placeholders: `${WOODPECKER_AGENT_SECRET}`, `${WOODPECKER_FORGEJO_CLIENT}` and `${WOODPECKER_FORGEJO_SECRET}`. Birth fills the shared agent secret offline and its first-boot setup fills the Forgejo OAuth application values. The callback is `https://ci.home.arpa/authorize`. The template is not a maintenance overwrite: generated values stay on the appliance. Both units use `/opt/woodpecker/woodpecker-server` and `/opt/woodpecker/woodpecker-agent`, respectively, and run as `woodpecker`. HTTP and gRPC bind to loopback ports 8000 and 9000. Nginx serves the HTTPS name and Unbound resolves it.

The local backend executes workflow commands directly as the agent user, without isolation; only trusted repositories and workflows should be allowed. The shared environment also exposes its secrets to both processes. Forgejo's local webhook policy and the certificate trust for `git.home.arpa` must permit the server to communicate; these are integration prerequisites outside this module.

Upstream Woodpecker 3.18 configuration: https://woodpecker-ci.org/docs/3.18/administration/configuration/server (host, listeners, admin, registration and shared secret); https://woodpecker-ci.org/docs/3.18/administration/configuration/forges/forgejo (Forgejo URL, OAuth and callback); https://woodpecker-ci.org/docs/3.18/administration/configuration/agent (backend, gRPC address, agent secret and config file); https://woodpecker-ci.org/docs/3.18/administration/configuration/backends/local (local execution and trust boundary).
