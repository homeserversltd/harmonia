# sway

Adds a Sway desktop module immediately after the retained `hyprland` module and spine seat. The repair ruling removes only the named Bitwarden wrapper payload, its two manifest entries, and its autostart invoking line; other Hyprland source is retained unchanged. The ladder manages exactly thirteen (13) files declared in `manifest.json`: `.config/sway/config`, `.config/sway/conf.d/output.conf`, `.config/sway/conf.d/input.conf`, `.config/sway/conf.d/bindings.conf`, `.config/sway/conf.d/look.conf`, `.config/sway/conf.d/windows.conf`, `.config/sway/conf.d/60-waybar-floats.conf`, `.config/sway/conf.d/autostart.conf`, `.config/systemd/user/hometv-sway-session.target`, `.config/wofi/config`, `.config/wofi/style.css`, `.config/systemd/user/hometv-sway-environment.service`, and `.config/systemd/user/graphical-session.target.d/10-hometv-sway-environment.conf`. Wofi inputs are byte-identical to the former launcher-bin payload and are now owned by Sway. `input-overrides.conf` is not managed or created by this module: `input.conf` includes the unmanaged operator/Caduceus seed after Sway defaults so local overrides retain precedence.

The binding source table is in the ignored author output at `target/tv-sway-repair-1/tv-author/bindings-table.txt`. It accounts for all 42 actual Hyprland directives (39 keyboard, 3 mouse); the one deliberate omission is source line 32, `SUPER K resizeactive`, because `SUPER K` remains `kcalc` under the explicit ruling. Sway has no `initial_class` criterion, so the equivalent extension class and initial-class source rules are represented by the same Xwayland `class` selector. Bitwarden title selectors are split into native `app_id` + title and Xwayland `class` + title forms; both preserve the title match across both window protocols. `floating_modifier Mod4 normal` carries the ordinary Super+left move and Super+right resize behavior. The distinct Super+Shift+left gesture is bridged by one mouse binding that runs `seat - cursor press button3` then `seat - cursor release button3`: the synthetic right-button press enters Sway's native Mod4 resize path while physical left remains held, and the physical release ends the native operation. This supported cursor-command path exists in Sway 1.10.1 and 1.12, but `sway-input(5)` marks it deprecated in favor of the virtual-pointer Wayland protocol. It needs no helper or package, and Sway's native floating resize retains Shift's aspect-ratio constraint. This is not a `resize` command, and config validation alone does not prove the runtime gesture.

The one direct Sway `exec` invokes `/usr/bin/flock --exclusive` on `$XDG_RUNTIME_DIR/hometv-sway-handoff.lock` around `/usr/bin/systemd-run --user --wait --collect --service-type=oneshot`. Its transient bootstrap has an `ExecCondition` that probes the captured `${SWAYSOCK}` with `/usr/bin/swaymsg --quiet --socket=${SWAYSOCK} --type=get_version` before any target stop or environment mutation; an old/dead queued callback skips without clobbering a newer session. `ExecStartPre` stops `hometv-sway-session.target` and `graphical-session.target`; the transient service receives `WAYLAND_DISPLAY` and `SWAYSOCK` from that exact Sway descendant via `--setenv` without values and seeds them into D-Bus and the user manager with `/usr/bin/dbus-update-activation-environment --systemd WAYLAND_DISPLAY SWAYSOCK`. Its synchronous `ExecStartPost` starts `hometv-sway-session.target`. The flock command-form lease remains held through `systemd-run --wait`, including successful completion of this post-start target request. This is an ephemeral native bootstrap in addition to the one managed importing unit; it is not one runtime process.

The managed `hometv-sway-environment.service` is `Type=oneshot` with no `RemainAfterExit`; it owns the thirteen static values from the retained Hyprland `envs.conf`, with `XDG_SESSION_DESKTOP` and `XDG_CURRENT_DESKTOP` set to `sway`. Dynamic `WAYLAND_DISPLAY` and `SWAYSOCK` are inherited from the user manager only after the serialized bootstrap seeds them. Native `ExecStartPre` tests require both dynamic values and check live Sway IPC. Two serial `ExecStart` commands import all fifteen names: first into D-Bus activation with `--systemd`, then into the user systemd manager. The managed unit is `Before=` both session targets and `hs-waybar.service`/`hs-dunst.service`; `hometv-sway-session.target` adds `Requires=`/`After=` for the importer and retains `BindsTo=graphical-session.target` plus its existing pre-target relationship. The Sway-owned `graphical-session.target.d/10-hometv-sway-environment.conf` also adds `Requires=`/`After=` so the graph’s Waybar/Dunst wants cannot start after importer failure. The transient bootstrap has no `OnSuccess`, `Conflicts`, or `Before` target edges. No Sway, systemd, D-Bus, or face runtime action or proof was run while authoring this source.

Sway has no `initial_class` distinction and no native configurable shadow, blur, or compositor-animation controls corresponding to the Hyprland source; its `default_border` and gaps are explicitly disabled, and no gesture binding, swayidle, lock, or screen-blanking policy is added. The source's four `movetoworkspace` lines are non-silent moves; their Sway bindings move to the adjacent previous/next workspace and then switch to that workspace to preserve follow behavior. The source has no `movetoworkspacesilent` dispatcher, so no separate silent binding is invented. No package installation, SDDM autologin, or live-session operation belongs to this module.
