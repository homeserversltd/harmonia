# Shared owner desktop streaming

HomeConsole and HomeSI link this one Sunshine job. The console pool renders its original `gamepad = ds5` configuration byte-for-byte and selects no owner-unit or service action. HomeSI selects `capture = wlr`, `upnp = disabled`, and `origin_web_ui_allowed = lan`; there is no bind narrowing, firewall, pairing PIN, or credential here. The router belongs to the household: the box never requests automatic forwarding, but this configuration makes no claim about a household-created port forward.

Birth supplies Sunshine, Sway, Kitty, Waybar, Wofi, Chromium, their desktop dependencies, and the owner user manager. This job never installs binaries. Owner settings retain Harmonia's native interactable disposition. The owner unit captures the display imported by Sway's socket-checked handoff, not a fixed display number or Hermes's private seat. It requires the owner's `sway-seat.service` and joins the shared `hometv-sway-session.target` (the existing TV compatibility name, not a connection to another body).

HomeSI's per-profile service values enable the owner desktop, bar and Sunshine. The helper runs as owner, waits for the desktop's session target, then starts the session services. The console's null values are a no-op, even if an operator has a local Sunshine unit. Config/unit proposals must exist before enablement; the native command step skips an absent owner Sunshine unit. No live operation is performed by authoring or rendering this module.

The full desktop is linked from the shared `sway`, `kitty`, `waybar`, and `chromium` jobs. HomeSI's Sway output and bindings and its Waybar values use native desktop controls rather than the TV-specific face routes. The owner unit's Debian payload lives at `sway-seat/files_root/desktop/platform/debian/sway-seat.service` and is selected by the HomeSI fragment link, not the global Debian pool: adding it globally would change the console's existing no-unit output. Hermes's own seat modules are untouched.
